# Architecture

01-core-infra is organized around a **template-driven, Ansible-automated** infrastructure model.

## Directory Layout

```
~/dev/01-core-infra/
  templates/infra/<component>/   ← Edit here (source of truth)
  ansible/                       ← Deployment automation
    ansible.cfg                  ← roles_path, inventory default
    inventories/local.yml        ← localhost connection
    playbooks/site.yml           ← main playbook (roles in order)
    roles/
      base/                      ← apt packages, system setup
      tools/                     ← CLI tools with sentinel-based idempotency
      templates/                 ← deploy infra components
      systemd/                   ← systemd units + sudoers
      cron/                      ← cron jobs (backup + healthcheck)
      mesh_sync/                 ← credential sync engine
  plex/ portainer/ qbittorrent/  ← NEVER TOUCH (generated by Ansible)
  scripts/
    deploy.sh                    ← Full deployment logic
  backup.sh                      ← Automated backup script
  healthcheck.sh                 ← Container and service health monitoring
```

## Naming Convention

The prefix of each component directory determines its deployment target:

| Prefix | Target | Description |
|--------|--------|-------------|
| `01-core-*` | `~/dev/01-core-infra/<name>/` | Inside this repo, generated by Ansible |
| `04-network-*` | `~/dev/04-network-<name>/` | Sibling repo, network components |
| `02-*` | `~/dev/02-<name>/` | Own git repo (cloned via manifest) |
| `06-*` | `~/dev/06-<name>/` | Own git repo (cloned via manifest) |

## Ansible Role Execution Order

The playbook (`playbooks/site.yml`) runs roles in this order:

1. **base** — System packages, essential setup
2. **tools** — CLI tools (Docker, NVM, Node.js, Tailscale, Ollama, etc.)
3. **templates** — Deploy infrastructure components from templates
4. **systemd** — Systemd unit files and sudoers configuration
5. **cron** — Scheduled backup and healthcheck jobs
6. **mesh_sync** — Credential sync engine

## Tool Sentries

Each tool in `roles/tools/defaults/main.yml` has a **sentry command** — Ansible checks if the tool exists before installing. This makes the playbook idempotent:

```yaml
# Example sentry entry
docker:
  command: docker --version
nvm:
  command: nvm --version
```

To add a new tool, add a sentry entry here first, then implement the installation task.

## Repo Manifest

`templates/infra/repos.manifest.jsonc` declares git-repo identity for components that are separate git repositories:

```jsonc
{
  "02-ai-llm-infra-sync": {
    "remote": "git@github.com:Aldo-f/02-ai-llm-infra-sync.git",
    "ref": "main",
    "infraSubdir": "infra/"
  }
}
```

The deploy process clones or pulls the repo, checks out the specified ref, and copies only the `infra/` subdirectory — preserving `.git` and application source code intact.

## Workflow

1. Edit templates in `templates/infra/<component>/`
2. Run `ansible-playbook -i inventories/local.yml playbooks/site.yml`
3. Ansible deploys the changes to the runtime target
4. Systemd units and cron jobs are updated as needed
5. Mesh sync distributes credentials

**Never edit runtime directories directly** — always edit templates and deploy.
